# 実装済みのラスタライザが「呼ばれていない」ことは、テストでは見えない

## 何が起きていたか

`SpriteRaster` (`src/x68k/core/video/sprite_raster.cpp`) は完成していた。

- PCG の 8x8 / 16x16 レイアウト、128 個のレジスタ配置、座標の 16 の下駄、
  反転、プライオリティ、1 ライン 32 個の上限、BG のネームテーブルと
  スクロールと巻き戻し — **テスト 37 ケースが全部通っていた**
- スプライトレジスタ ($EB0000) と PCG VRAM ($EB8000) は
  CPU バスに読み書き両方向で配線済み (`machine.cpp:1105-1276`)。
  **ゲストからスプライトをプログラムすることは、ずっとできていた**

それでも**スプライトと BG は 1 ドットも画面に出なかった**。

`SpriteRaster::renderPlane()` の**呼び出し元が 0 件**だったため。
合成しているのはホスト (`host/main.cpp`) も実機 (`display_lcd.cpp`) も
`TextRaster::render` と `GraphicRaster::composite` の 2 つだけで、
`graphic_raster.cpp` には sprite という語が 1 つも出てこない。

## なぜテストで見えなかったか

テストが検査していたのは「**ラスタライザ関数が正しく描く**」ことで、
「**その絵が画面に届く**」ことではない。この 2 つは別の主張で、前者が
いくら厚くても後者は保証されない。

同じ構造は他の場所にも起こりうる。**「実装した」と「繋いだ」の間には
テストの空白がある**。単体テストは部品の正しさを測る道具であって、
部品が組み立てられていることは測らない。

見つけ方は単純で、**公開 API の呼び出し元を grep する**。呼び出し元が
0 件の公開関数は、テストが何ケース通っていても死んでいる。

## どう直したか

重ね順を知る場所を `Compositor` (`src/x68k/core/video/compositor.cpp`)
1 つに閉じ込め、ホストと実機の両方がそこを通るようにした。

重ね順は奥から **グラフィック/テキスト → BG1 → BG0 → スプライト**。

- **Why not それぞれの呼び出し側で 2 つを順に呼ぶか**: 同じ重ね順が
  2 か所に複製され、一方だけ直したときに「ホストでは出るが実機では
  出ない」が生まれる。実際この不具合は、両方が同時に同じ抜けを
  持っていたから長く気付かれなかった
- **Why not `GraphicRaster::composite` にスプライトを足すか**: あちらは
  VideoController だけで完結する面を扱う。スプライトと BG は Sprite
  (CYNTHIA) という別デバイスなので、持ち込むと依存が増える

実機側は `shouldComposite()` の条件にスプライト面を足した。BG と
スプライトだけで絵を作り G-VRAM を使わないゲームが、テキスト単独の
安い経路へ落ちて何も出なくなるのを防ぐため。

## 既存の表示経路を壊していないことの確かめ方

**PPM の MD5 を変更前後で比べる。**

```
./build-host/x68k-run --iplrom rom/iplrom.dat --hdd rom/hdd0.hdf \
  --cycles 400000000 --event-driven --ppm /tmp/out.ppm
```

Human68k のコンソールを出した状態で `c334588e6118f06794510c5e9059236c`
が変更前後で一致した。**1 ドットも変わっていない**ことがこれで言える。

テストが緑になることより、この一致の方が「既存の経路を壊していない」
ことの証拠として強い。テストは書いた範囲しか見ないが、画面全体の
ハッシュは書き忘れた範囲も含めて見るため。

## まだ確かめられていないこと

- **スプライト面のプライオリティ ($E82500 の bit13-12)** は解釈していない。
  レジスタに 2bit あることは分かっているが、IPL-ROM はスプライトも BG も
  一切表示しないので、実機でどう効くかを ROM から確かめる手立てが無い。
  確かめられない規則を実装すると「テストは通るが実機と違う」を作り込む
  ことになるので、**スプライト面は最前面に固定**してある
- スプライト属性 +4 の反転ビットとパレットブロックの位置も同じ理由で未検証
  (`sprite.h:164-180`)
- テキスト/スプライトのパレットは 16 色しかない (実機は 16x16=256)。
  パレットブロックを使い分けるソフトでは色が化ける。直し方は
  `sprite_raster.h:12-24` に書いてある
