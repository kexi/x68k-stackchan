# X68000 エミュレータ実装の落とし穴

実物の IPL-ROM で起動を試して初めて分かった問題を記録する。いずれも
**合成 ROM や 68000 の命令テストベクタでは検出できなかった**もので、
症状は「何も起きずに固まる」「原因不明の暴走」という形でしか現れない。

同じ轍を踏まないため、症状 → 原因 → 見分け方の順で残す。

## 1. RESET 命令が $000000 の ROM 写像を解除する

**症状**: 777 命令でサブルーチンから戻れなくなる。RTS がスタックから
読んだ戻り先が明らかにおかしい値になる。

**原因**: X68000 はリセット直後、ベクタを読むために `$FF0000` の内容が
`$000000` へ写像される。これを解除するのは**エリアセット (`$E86001`) への
書き込みではなく、`RESET` 命令**だった。IPL-ROM は `$FF001A` で `RESET` を
実行して通常のメモリ配置へ切り替える。

68000 としての `RESET` は外部へ信号を出すだけで CPU 自身は何もしないため、
「何もしない命令」として実装しがちだが、機種固有のこの反応を落とすと
RAM を読んでも ROM の値が返り続ける。

**見分け方**: RTS の戻り先が奇数だったり、明らかに ROM 内のコードを
指していたら、RAM が読めていない可能性を疑う。バス経由で読んだ値と
実際の RAM の内容を突き合わせると一発で分かる。

## 2. 写像されるのは ROM の先頭ではなく $FF0000 側

**症状**: リセット直後に `SSP=FFFFFFE3` のような無意味な値になり即座に暴走。

**原因**: `$000000` へ写像されるのは IPL-ROM の先頭 (`$FE0000`) ではなく
`$FF0000` の側。リセットベクタと起動コードはそこに置かれており、実行は
`$FF0010` から始まる。

**見分け方**: リセット直後の SSP と PC を出す。実機は `SSP=$002000`,
`PC=$FF0010` になる。

## 3. 例外フレームの書き込み位置にアドレスマスクをかけてはいけない

**症状**: 割り込みからの復帰で PC の上位バイトにゴミが乗る
(`$00FF0544` になるべきところが `$1EFF0544`)。

**原因**: 例外フレームを積むとき、SP に `0x00FFFFFE` のマスクをかけていた。
奇数 SP でも書けるようにという配慮だったが、RTE 側は `read32(a7)` で
読み戻すので、書き込み位置と読み出し位置が 1 バイト食い違う。

**見分け方**: PC の上位 8bit が 0 でなくなった瞬間を捕まえる。
そこから遡ると例外処理に行き着く。

## 4. MFP は自動ベクタではなく自前のベクタ番号を返す

**症状**: 起動が進んだ後、画面に「エラーが発生しました。リセットして
ください。」(Shift_JIS) を出して停止する。

**原因**: X68000 の MFP (MC68901) は自動ベクタ (24+level) ではなく、
VR レジスタの上位 4bit と割り込み番号を組み合わせたベクタ番号を返す。
自動ベクタで処理すると、IOCS が未初期化ベクタ用に埋めている
「上位バイト = ベクタ番号」の値 (`$1EFF0540` のような形) を PC に
読み込み、不正ベクタのハンドラへ飛んでしまう。

**見分け方**: 割り込み受理の瞬間に飛び先を出す。IOCS のベクタテーブルを
ダンプすると `$43FF0540`, `$44FF0540` のように上位バイトだけが違う値が
並んでいるのが見える。これが「未初期化」の印。

**関連**: この仕組みのため、PC は 32bit のまま保持し、丸めるのは
バスへ出す瞬間だけにする必要がある。PC 自体を 24bit に丸めると
68000 のテストベクタ (32bit の PC を期待する) が落ちる。

## 5. MFP の送信状態レジスタは空きビットを立てておく

**症状**: `$FF61C8` のポーリングループから抜けられない。

**原因**: IPL-ROM はキーボードへコマンドを送る前に TSR (`$E8802D`) の
bit7 (送信バッファ空き) を待つ。0 で初期化していると永久に待つ。
エミュレータは送信を即座に完了したものとして扱うので、常に空いて
いることにしてよい。

## 6. アドレスレジスタと PC は 32bit で保持する

**症状**: 68000 のテストベクタが軒並み落ちる
(`A0: got 00C321E4 want F9C321E4`)。

**原因**: 68000 のアドレスバスは 24bit だが、**内部のレジスタは 32bit**。
上位 8bit が捨てられるのはバスへ出す瞬間だけ。レジスタ側でマスクすると
`A0` に `$F9C321E4` を入れて読み出したときに `$00C321E4` が返るという
実機と違う挙動になる。

## 起動の進み方を測る目安

実測値。ここより手前で止まったら上記のどれかを疑う。

| 到達点 | 命令数の目安 |
|---|---|
| IOCS ベクタテーブルの初期化 (256 エントリ) | 約 780 |
| テキスト VRAM のクリア開始 | 約 3,800 |
| MFP タイマ割り込みの受理 | 約 30 万 |
| テキスト VRAM のクリア完走 (4 プレーン) | 約 4,500 万 |

## デバッグの道具立て

`host/main.cpp` (`just run`) に用意してある。

- `--trace-last N`: 停止直前の N 命令だけを出す。全トレースは数百万行に
  なって使えないが、止まった理由は直前の流れに出る。
- `--stats`: 実行した命令を上位 4bit のグループごとに数える。
  どの命令群が使われているかで、実装の優先順位を決められる。
- `--ppm PATH`: テキスト画面を PPM で書き出す。依存ライブラリが要らない。

IPL-ROM が出力しようとしている文字列を読むと、エラーの内容が直接分かる
(Shift_JIS でデコードする)。文字列出力ルーチンは `$FF721E` で、
`A1` が文字列の先頭を指す。
