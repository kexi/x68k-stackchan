# 何が律速していたか

実機 CoreS3 で fps が 20.8 から動かなかった。ゲスト側を 4bit にして
描画を 360,768 -> 81 cycles にしても 20.8 のままだったので、
ゲストでも合成でもないと分かっていた。

Core0 (表示コア) を計測して分解した。5 秒間:

| 項目 | 時間 | 占有 |
| --- | ---: | ---: |
| LCD 転送 (pushFrame) | 3,291.8ms | 65.8% |
| M5.update + キー + コンソール | 76.4ms | 1.5% |
| **vTaskDelay と顔処理** | **1,631.8ms** | **32.6%** |

ループは 5 秒で 204 周しか回らず、そのうち転送できたのは 102 枚。
**残り 102 周は「フレームが無い」ので 16ms 眠っていた。**

  102 枚 x 32.3ms + 102 回 x 16ms = 4,927ms ≒ 5,000ms

と辻褄が合う。**5 秒のうち 1.6 秒 (32%) を寝て過ごしていた。**

# 直し方

`vTaskDelay(pdMS_TO_TICKS(16))` を `vTaskDelay(1)` にする。1 行。

LCD 転送は 1 枚 32.3ms かかり、その間に Core1 は次のフレームを作り終えて
いる。16ms 眠ると、出来上がっているフレームを取りに行くのが遅れる。

完全に消さないのは、1 tick も譲らないと idle task が走れずウォッチドッグが
鳴るため。1 tick (1ms) なら譲りつつ待ちは最小になる。

**実機で 20.8 -> 26.6fps。** 転送枚数は 5 秒で 102 -> 133 枚に増えた。

# 残る壁は 31fps。これは構成上の上限

転送 1 枚 32.2ms は変わらない。逆算すると実効 38.2MHz で、
CoreS3 の ILI9342C を 40MHz で駆動したときのほぼ上限にあたる。
SPI クロックを上げる余地は無い。

時間は `pushImageDMA` の**中**にある。`waitDMA()` を後ろから外して
非同期化を試したが fps は変わらなかった (26.58 -> 26.56、誤差)。
待ちではなく変換が支配的だという証拠なので、この変更は戻した。

変換が要るのは `setSwapBytes(true)` のため。フレームバッファは PSRAM に
あり、M5GFX 0.2.26 は PSRAM から直接 DMA できない (ESP32-S3 の
`esp_cache_msync` を持たない) ので、内部の DMA 可能バッファへ画素を
写してから送る。このコピーが 32.2ms である。

内部 RAM へ置ければ変換は要らなくなるが、**入らない**:

- フレームバッファ 1 枚 320x240x2 = 153,600 byte、2 枚で 300KB
- 実機の内部 RAM 空き **49,619 byte** (最大ブロック 31,744)

**訂正**: ここで「30fps には 33.3ms 以内が要るところ 32.2ms しか余裕が無く
ぎりぎり」と書いたのは誤りである。32.2ms は 33.3ms より**短い**ので、
転送時間の側は 30fps を妨げていない。1.1ms の余裕がある。
上限は 31.0fps で、30fps はその内側にある。

届いていない理由は転送ではなく、**フレームバッファが 2 枚しかないこと**である。

Core0 は転送中の 32.2ms のあいだ 1 枚を掴んだままになる (`isFrontInUse_`)。
残る 1 枚に Core1 が書いても、front が使用中のうちは publish できない。
実測で backpressure が 490 回/5秒 立っており、Core1 は 1 枚 2.43ms で
描けているのに置き場所が無くて待っている。

その結果 1 枚あたり 37.6ms かかっている (転送 32.2ms + 隙間 5.4ms)。
この 5.4ms は「転送が終わってから次を publish するまで」の往復である。

## 効かなかった対策 (記録)

- **RenderBudget の interval を 33,333 -> 25,000us**: 26.6fps のまま変わらず。
  生産周期が律速ではなかった。33,333 へ戻した。
- **転送直後に眠らない**: 26.6fps のまま。空振りはむしろ 569 -> 771 回へ増えた。
  転送から戻った時点で次の 1 枚が用意できていないため。
- **waitDMA の非同期化**: 26.58 -> 26.56fps。時間は待ちではなく
  `pushImageDMA` の中の変換にある。

## 30fps へ届かせるには

フレームバッファを **3 枚**にする。転送中でも Core1 が書いて publish できる
ようになり、隙間の 5.4ms が埋まって 31.0fps まで出せる。

PSRAM は 3.7MB 空いており 1 枚 150KB は入る。ただし `FrameChannel` は
`writeBuffer_` / `frontBuffer_` の 2 変数で 2 枚を前提にしており、
`TiledCompositor` も buffer index 0/1 で世代を持つ。両方の不変条件を
触る変更になる。

余裕は 1.1ms (3.4%) しかないので、転送が 1 度でも遅れれば 30 を割る。
