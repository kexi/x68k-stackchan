# X68000 のブートシーケンス

エミュレータ実装のマイルストーン（M2〜M3）の受け入れ基準はこの流れに対応する。

## Phase 1: リセット〜IPL-ROM の初期化

以下は EXPERT 用 IPL-ROM v1.0 の実測（本エミュレータで実行して確認）。

1. 68000 リセット。ベクタから **SSP = `$002000`、PC = `$FF0010`** を読んで実行開始。
   - ⚠️ `$000000` へ写像されるのは ROM の先頭（`$FE0000`）ではなく **`$FF0000` 側**。
   - `$FF0000` の 8 バイトは実測で `00 00 20 00 00 FF 00 10`。
2. `$FF0010`〜`$FF001A`: SR を設定し、A7 を張り直して `RESET` を実行。

   ```
   FF0010: 46FC 2700        MOVE #$2700,SR      ; 割り込み禁止
   FF0014: 4FF9 00002000    LEA $002000,A7      ; SSP を明示的に設定し直す
   FF001A: 4E70             RESET               ; ← ROM 写像の解除
   ```

   - ⚠️ **`RESET` 命令（`4E70`）が `$000000` の ROM 写像を解除する**。
     エリアセットへの書き込みではない。68000 の `RESET` は外部へ信号を
     出すだけなので「何もしない命令」として実装しがちだが、落とすと
     RAM を読んでも ROM の値が返り続ける。
   - 位置は **`$FF001A`**。`$FF0010` は `MOVE #$2700,SR` であって
     `RESET` ではない。
3. `$FF0024`: `BSR $FF0510` で IOCS ベクタテーブルを初期化（約 780 命令）。

   ```
   FF0510: 223C 01000000    MOVE.L #$01000000,D1
   FF0516: 343C 00FF        MOVE.W #$00FF,D2     ; 256 エントリ
   FF051A: 20C0             MOVE.L D0,(A0)+
   FF051C: D081             ADD.L D1,D0          ; 上位バイトを +1
   FF051E: 51CA FFFA        DBRA D2,$FF051A
   ```

   - `D0` の初期値は `$FF0540`（`$FF001E` の `MOVE.L #$FF0540,D0`）、
     `A0` は `$FF001C` の `SUBA.L A0,A0` で 0。つまり
     `$000000` から 256 エントリぶんに **`$00FF0540` を起点として
     上位バイトだけ +1 した値**を埋める（`$00FF0540`, `$01FF0540`,
     `$02FF0540` …）。そこへ飛んだら不正ベクタとして扱う仕組み。
   - なお **IOCS のコールベクタ（`$000400`〜）はこれとは別物**。
     そちらは `$FF1B32` からの 224 エントリを `$000400` へコピーし、
     末尾 3 本（`$FD`/`$FE`/`$FF`）を個別に上書きして作る。
4. MFP・CRTC・ビデオコントローラ・システムポートを初期化。
   - テキストパレットが設定される（色 1 = シアン、色 2 = 黄、色 3 = 白）。
   - テキスト VRAM を 4 プレーン分クリア（約 4,500 万命令かかる）。
5. SRAM (`$ED0000`) のマジック `"X68000"` + `$57` を検査。壊れていれば初期化する。
   CLR キーを押しながらの起動で強制初期化（IPL-ROM 1.1 以降）。

### エリアセット (`$E86001`) について

IPL-ROM 1.3 以降はここへ `CLR.B` で書き込む、とされる（**資料ベース。
本プロジェクトが持つ v1.0 の ROM では未確認**）。68000 の `CLR` は
read-modify-write として実装されており、実機は「読んでから書く」ため、
**このアドレスの読み出しに副作用を持たせると 1.3 以降が起動しない**、
というのが資料の主張。

一方 v1.0 の実測では、`$000000` の写像解除は **`$FF001A` の `RESET`
命令**が担っていた。エリアセットは別の役割（スーパーバイザ領域の設定）
を持つと思われる（**推測。裏取りできていない**）。

## Phase 2: SRAM から設定を読む

| アドレス | サイズ | 内容 |
|---|---|---|
| `$ED0000` | 8B | マジック `"X68000"` + メモリチェックデータ `$57` |
| `$ED0008` | 4B | **メインメモリ実装容量**（`$00100000` = 1MB、`$00200000` = 2MB） |
| `$ED000C` | 4B | ROM 起動アドレスポインタ（`$00FC0000`） |
| `$ED0010` | 4B | SRAM 起動アドレス（`$00ED0100`） |
| `$ED0018` | 2B | **最優先起動デバイス**。`$0000` = 標準優先順位 |
| `$ED001A` | 2B | RS-232C 設定 |
| `$ED001D` | 1B | 起動時画面モード（初期値 16） |
| `$ED002E`〜 | — | テキストパレット 0-15 のシステム規定値 |

エミュレータは**この初期値を正しく作らないと起動しない**。

## Phase 3: 起動デバイスの探索

IPL-ROM 1.6 の標準優先順位:

1. フロッピーディスク
2. SASI ハードディスク
3. ROM 内蔵 SCSI ハードディスク / CD-ROM
4. RAM（バッテリバックアップ SRAM 含む）

> **実装上の判断**: エミュレータの最小経路としては **SASI 起動が有利**。
> FDC (uPD72065) はデータ転送が DMAC 経由になるため DMAC ch0 の実装も必要になるが、
> SASI は TEST UNIT READY / READ / WRITE / REQUEST SENSE 程度で足りる。

## Phase 4: ブートセクタの実行

- IPL-ROM がディスク先頭から **1024 バイトを `$002000` に読み込んで実行**する。
- ブートセクタは **1024 バイト以内**、かつ **先頭バイトは `$60` (`BRA`)**
  でなければならない（`$FF02BE` の `CMPI.B #$60,(A1)` で検査。実測）。
- 読み込みは **IOCS `$47`（ドライブの準備）→ IOCS `$46`（実際の読み出し）**
  の順で行う。`$FF029C` からの実測。詳細は
  [SASI 起動経路](x68000-sasi-boot.md#7-ブートコードから使える-iocs) にある。
- ⚠️ **SASI 起動では読まれる位置が LBA 0 とは限らない。** 識別子 `"X68K"`
  は LBA 4、実行されるコードは LBA 0。詳細は SASI のドキュメント。

## Phase 5: ブートセクタによる HUMAN.SYS のロード

以下は **FD 起動を前提とした資料ベースの記述**で、本プロジェクトの
SASI 経路では未検証。SASI 経路で実測できているのは Phase 4 まで。

1. `IOCS _BOOTINF` で起動ドライブ情報を取得
2. `IOCS $46` (B_READ) で FAT のルートディレクトリ先頭セクタを読む
3. ルートディレクトリの**先頭から 32 エントリ以内**に `human.sys` を探す（大小文字無視）
4. 見つかったエントリの開始クラスタ番号をセクタ番号に変換
5. 先頭セクタを読み、X68k 実行ファイルヘッダ（先頭 `'HU'`）を検証
6. **ロード先固定形式で、ロードアドレスが `$006800`** であることを確認
   （Human68k 3.02 の HUMAN.SYS はヘッダの実測でロード・実行開始とも `$006800`）
7. `IOCS $46` (B_READ) で **`$0067C0` から text+data+`$40` バイト**をロード
   （`$40` は実行ファイルヘッダのぶん）
8. BSS 領域をゼロクリア
9. ヘッダの実行開始アドレスへジャンプ

> ⚠️ **制約**: `human.sys` は**連続したセクタに配置されている必要がある**。
> ブートセクタは FAT チェーンを辿らないため。ディスクイメージを自作する場合の要件。

## Phase 6: Human68k 本体

1. HUMAN.SYS（カーネル）起動
2. `CONFIG.SYS` を読む（デバイスドライバ、`FILES=`、`BUFFERS=` 等）
3. シェル起動（既定 `COMMAND.X`）
4. `AUTOEXEC.BAT` 実行
5. **`A>` プロンプト**

## エミュレータの実装順序

[tyfkda 氏の手法](https://tyfkda.github.io/blog/2015/03/01/x68k-emu.html)に倣い、
**未実装命令は assert で落とし、IPL-ROM が実際に実行した命令から順に実装する**。
IPL-ROM 自身が「何が必要か」を教えてくれるので、仕様書を先に読み込むより速い。

1. 68000 コア + RAM + IPL-ROM を `$FF0010` から実行
2. エリアセット（`$E86001`）→ IPL-ROM が先へ進む
3. SRAM に正しい初期値を配置
4. CRTC + ビデオコントローラ + テキスト VRAM + パレット → 起動画面が出る
5. MFP（タイマ + 垂直帰線割り込み）→ 時間が進む
6. スタブ群（RTC / OPM / ADPCM / SCC / PPI / システムポート）
7. SASI（または FDC + DMAC）→ ブートセクタが `$002000` にロードされる
8. FAT12 → HUMAN.SYS が `$006800` にロードされる
9. MFP のキーボード受信 → 入力できるようになる

## 未検証の項目

- IPL-ROM が周辺回路を初期化する具体的な順序（一次資料が見つかっていない）。
  実装時は IPL-ROM のトレースログから逆に追う方針。
- IPL-ROM のバージョンごとの差異（1.0 / 1.1 / 1.2 / 1.3）の詳細。
